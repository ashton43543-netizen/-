# Arcane Drift — Unity 2D 프로젝트 (무한 모드)

claude.ai 채팅에서 진행한 인수인계 문서를 바탕으로, **무한 모드**로 처음부터 새로 만드는 프로젝트다.
원본 게임은 HTML 프로토타입 `arcane-drift.html` 이다. **이 파일은 아직 이 리포지토리에 없다.**

## 작업 방식 (반드시 지킬 것)

- ~~한 단계씩 진행한다.~~ 사용자 요청으로 STEP 1~8을 한 번에 작성했다 (2026-10-30). 이후 수정은 사용자의 실행 결과를 받아 진행한다.
- 사용자는 Unity 초보다. **에디터 설정 없이 파일 하나(`Assets/Scripts/ArcaneDriftGame.cs`)만 넣고 ▶ 로 실행되는 구조**를 유지한다 (설계 결정 11). 새 STEP 마다 이 파일을 교체하는 방법만 알려준다.
- 사용자는 답변에 **'적대적 검증'**을 원한다: 주장의 근거가 실제로 성립하는지 먼저 확인하고, 가장 강한 반론을 함께 제시하며, 결론이 안 난 쟁점은 그렇다고 밝힌다.

  - 무한 모드 때문에 **새로 생긴 수치**(아래 2-1)와 원본을 확인 못 해 **임시로 정한 수치**는 코드 주석에 그렇다고 적는다.

## 2. 게임 개요

- LoL식 **우클릭 조작**: 빈 땅 우클릭 = 이동, 적 위 우클릭 = 그 적을 추격하며 사거리에서 자동 반복 공격. 새 명령 전까지 유지.
- 적을 잡아 XP 획득 → 레벨업 시 **증강 카드 4장 중 1장** 선택 (일시정지)
- 스킬 Q·W·E는 **처음엔 잠겨 있고** 증강 카드로 해금 → 레벨업(최대 5) → 진화
- 엘리트 22초마다, 보스 90초마다
- **무한 모드**: 클리어가 없고, 플레이어가 죽으면 게임 오버. 기록(생존 시간·처치 수)과 최고 기록을 보여준다.
  - 원본은 6분 최종 보스 처치 = 승리 구조였다. OT 권장(무한 모드)과 상호 플레이 투표(기록 경쟁)를 근거로 무한 모드로 바꿨다.

## 3. 확정된 설계 결정

1. **단위 변환**: HTML은 픽셀, Unity는 유닛. **Pixels Per Unit = 100, 모든 거리·속도 ÷ 100.** 시간(쿨다운, 공속, 스폰 간격)은 그대로.
2. **카메라**: Orthographic, Size **4.5** (`ArcaneDriftGame` 이 시작할 때 직접 설정)
3. **물리 미사용**: Rigidbody2D 없이 `transform.position` 직접 이동 (원본과 동일). 충돌 판정은 거리 계산 / OverlapCircle.
4. **스탯 구조**: 원본의 `player.mods` 객체를 **그대로 C# 클래스(PlayerMods)로 옮긴다.** 증강은 값을 더하기만 한다 (제거 기능 불필요).
   - ※ 채팅 초반에 설계했던 `StatSheet / CharacterStat / StatModifier` 시스템은 **폐기**했다. 과설계였고 관통·폭발·연쇄 같은 효과를 표현할 수 없다.
5. **증강 데이터**: ~~ScriptableObject~~ + `ModOp` 열거형 + `List<ModEffect>`. 적용은 `AugmentApplier.Apply()` 의 switch 한 곳에서 처리.
   - ⚠️ 결정 11(단일 파일)과 충돌한다. ScriptableObject 는 클래스 이름과 같은 파일이 따로 있어야 에셋으로 만들 수 있다. **STEP 5에서 결정**: 코드 안의 데이터 표로 둘지(단일 파일 유지), 증강만 별도 파일로 뺄지(기획 담당이 에디터에서 수정 가능).
6. **스프라이트**: 흰 원 하나를 만들어 `SpriteRenderer.color` 로 색만 바꿔 사용 (원본이 원으로 그림). 에셋 교체는 미션 3에서.
7. **평타 경직(attackLock)**: 원본처럼 발사 직후 `min(0.22, 0.4/aspd)` 초 동안 이동 불가, **캔슬 불가**로 먼저 구현. 플레이해 본 뒤 캔슬 추가 여부 결정 (추가 시 우클릭 이동 명령에서 attackLock = 0).
8. **풀링 필수**: 적·투사체·XP 오브. 6분 시점에 초당 약 30마리 스폰.
9. namespace는 `ArcaneDrift`.
10. **입력**: 모든 입력은 `GameInput` 을 거친다. 프로젝트 입력 설정(Old / New Input System / Both) 어느 쪽이어도 동작한다.
11. **단일 파일 + 자동 생성**: 게임 전체가 `ArcaneDriftGame.cs` 한 파일이다. `[RuntimeInitializeOnLoadMethod]` 로 씬이 열리면 게임 오브젝트를 스스로 만들고, 카메라·플레이어·배경·원 스프라이트도 코드로 만든다.
    - MonoBehaviour 는 `ArcaneDriftGame` 하나뿐이고, 나머지(Player, 적, 투사체 등)는 일반 C# 클래스로 두고 `ArcaneDriftGame.Update` 에서 돌린다. MonoBehaviour 를 여러 개 두면 각각 같은 이름의 파일이 필요해 단일 파일이 깨진다.
    - 대가: 파일이 길어진다(팀원과 같은 파일을 동시에 고치면 충돌), 인스펙터에서 수치를 바꿀 수 없다(수치는 파일 위쪽 상수로 모은다).

**검증한 것 (Unity 없이)**
- Unity API 대역(stub)으로 컴파일: 예전 Input Manager / 새 Input System 두 설정 모두 통과
- 대역 위에서 게임 루프를 봇으로 돌림: 무적 상태 14분(적 350마리 유지), 스킬 전부 진화 + 증강 전부 적용 8분, 일반 상태 여러 번. 예외 없음. 프레임당 평균 약 1.2ms (Mono 기준, 그리기 제외)
- **검증 못 한 것**: 실제 Unity에서의 화면·글꼴·입력·그리기 성능. 대역은 내가 아는 Unity API를 흉내 낸 것이라 API 사용 실수는 못 잡는다

### 결정이 필요한 쟁점

1. **원본 `arcane-drift.html` 이 없다.** 증강 25종의 효과, 적 종류 비율, 접촉 피해 방식, 보스 크기·탄막 수치 등은 새로 정했다 (코드에 `[임시]`). 원본을 구하면 맞춰야 한다.
   - 문서는 "증강 24종"이라고 했지만 등급별 개수(8+6+6+5)를 더하면 25다. 25종으로 만들었다.
2. **초반 난이도**: 서툰 봇은 20초 전후에 죽었다. 봇 탓일 수 있지만, 접촉 피해(`ContactCooldown` 0.7초마다 한 번)가 원본과 다를 수 있다. 원본이 "초당 피해 × dt" 방식이었다면 체감이 다르다.
3. **스킬 카드 가중치**: 해금 150, 강화 90 (`[임시]`). 70/45였을 때는 증강 20여 종에 묻혀 Q·W·E를 거의 못 봤다.
4. **스폰 거리 5.6~7.0 < 16:9 화면 가로 절반 8.0**: 적이 화면 좌우 안쪽에서 생긴다. 원본 수치라 그대로 두고 0.25초 페이드인만 넣었다.
5. **자동 공격**: 공격하던 적이 죽으면 근처 적으로 넘어가고, 가만히 서 있으면 사거리 안 적을 자동 공격한다 (`[임시]`, LoL 방식). 원본 동작 확인 필요.
6. **360초 대형 보스**: 원본 최종 보스 수치 그대로 360초마다 등장, 처치해도 계속. 사용자 확인 필요.
7. **증강 데이터**: 단일 파일을 지키려고 ScriptableObject 대신 코드 안 표(`Augments.Build`)로 만들었다 (결정 5와 다름).

## 6. 원본 핵심 수치 요약 (상세는 arcane-drift.html)

**적** (속도는 ÷100 적용값)

| key | 색 | 반지름 | HP | 피해 | 속도 | XP |
|---|---|---|---|---|---|---|
| grunt | #7a4fb0 | 0.13 | 16 | 6 | 0.95 | 2 |
| runner | #3fa789 | 0.10 | 10 | 4 | 1.65 | 2 |
| brute | #b0554f | 0.19 | 44 | 12 | 0.70 | 5 |

- HP 배율 `1 + elapsed/50`, 피해 `1 + elapsed/140`, 속도 `1 + min(elapsed/320, 0.7)` (elapsed는 초)
- ⚠️ 속도 상한 0.7이면 후반 runner가 플레이어보다 빨라진다 (1.65×1.7 = 2.8 > 2.5). 원본대로 구현 후 도망이 불가능하면 0.4로 낮추는 것을 검토. 무한 모드에서는 이 구간이 계속되므로 더 중요하다.
- 스폰 간격 `max(0.16, 1.05 - elapsed×0.002)`, 1회 스폰 수 `min(1 + floor(elapsed/35), 5)`
- 엘리트: HP×5, 피해×1.8, 속도×0.85, XP×6, 반지름×1.6, 색 #f0b429
- 보스: HP `650×(1+elapsed/70)`, 피해 `20×(1+elapsed/200)`, 속도 0.66, XP 120, 근접 시 6방향 탄막
- 최종 보스(무한 모드에서는 360초마다 대형 보스): HP `2200×(1+elapsed/70)`, 피해 34 기준, 속도 0.58, XP 300, 10방향 탄막

**플레이어**: HP 100, 공격력 10, 공속 1.1, 사거리 2.55, 이속 2.5, 치명타 5% / ×1.6

**XP 곡선**: `round(10 + level×7 + level²×0.6)`

**증강 등급 가중치**: common 100 / advanced 55 / rare 25 / legendary 8. 카드 4장. 진화 카드가 후보에 있으면 1장 확정.

**스킬 쿨다운**: Q `3.0 - lv×0.28`, W `6.5 - lv×0.5`, E `5.5 - lv×0.45`, 최소 1.2, × skillCdMult
- Q 아케인 볼트: 커서 방향 관통, 피해 `공격력×(1.8+lv×0.35)`. 진화 시 ×1.6 + 끝에서 폭발
- W 공허의 파동: 자기 중심 원형 피해 + 넉백, `공격력×(1.2+lv×0.3)`. 진화 시 ×1.5, 반경 +0.7, 0.6초 스턴
- E 섬광 돌진: 커서 방향 대시를 **14단계로 나눠** 이동하며 경로상 적 타격, `공격력×(1.1+lv×0.25)`, 사용 후 2초간 공속 +0.6. 진화 시 ×1.5, 대시 중 처치하면 쿨 70% 회복

**증강 24종** — 효과는 원본 `AUGMENTS` 배열 그대로 (common 8, advanced 6, rare 6, legendary 5; synergyFinale는 Q·W·E 모두 습득 시에만 등장)

## 7. 알려진 함정

| 증상 | 원인 |
|---|---|
| 총알이 같은 적을 영원히 못 맞힘 | 풀에서 꺼낼 때 `hitSet.Clear()` 누락 |
| 후반 프레임 급락 | 풀링 미적용, 멀어진 적 미회수 (무한 모드에서 특히 심함) |
| 대시가 적을 통과만 함 | 순간이동으로 구현 → 14단계로 나눌 것 |
| 카메라 떨림 | 카메라 이동을 Update에 둠 → LateUpdate |
| 증강 창 후 게임이 계속 멈춤 | 선택 후 `Time.timeScale = 1` 복구 누락 |
| 최대 체력 증강 후 체력 그대로 | 증가분만큼 현재 체력 더하기 누락 |
| 처치 폭발 연쇄로 프레임 튐 | 재귀 깊이 제한 플래그 필요 |
| 스크립트가 Add Component에 안 뜸 | 콘솔 컴파일 에러, 또는 파일명 ≠ 클래스명 (예: `CameraFollow (1).cs`) |
| 우클릭해도 안 움직임 | Game 창을 클릭하지 않아 포커스가 없음 |
| 플레이어가 두 개 / 클래스 중복 컴파일 에러 | 예전 5개 파일 버전(`PlayerController.cs` 등)이 프로젝트에 남아 있음 → 지우고 `ArcaneDriftGame.cs` 만 둔다 |
| "No script asset for ..." 경고 | 한 파일에 MonoBehaviour 를 두 개 이상 만듦 → 일반 클래스로 바꾼다 (결정 11) |
